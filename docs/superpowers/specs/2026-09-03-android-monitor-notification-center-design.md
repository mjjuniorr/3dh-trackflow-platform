# Android Monitor + Notification Center Design

Date: 2026-09-03

## Goal

Add a second Android application dedicated to real-time observation of all TrackFlow objects and add a server-side notification center for operational exceptions.

The existing courier Android application remains independent and unchanged in purpose.

## Android Monitor UX

The monitor application is intentionally minimal:

- map occupies the entire screen;
- all active objects with a last known location are shown in real time;
- top-right floating controls: notification bell and settings/overflow button;
- settings only controls local visibility of individual objects plus show-all/hide-all;
- visibility preferences are stored locally per Android device;
- hiding an object never changes backend state and never affects another user/device;
- initial camera fits visible objects once; live updates do not continuously steal camera control.

The monitor does not create deliveries, register couriers, send GPS, edit people, create public links or expose the administrative dashboard.

## Android project structure

Keep one Gradle root in `apps/android` and add a second application module:

```text
apps/android/
  app/       # existing courier app
  monitor/   # new read-only monitoring app
```

Expected application ID:

```text
br.com.tresdhmanaus.trackflow.monitor
```

## Realtime contract

The monitor reuses authenticated dashboard data:

1. authenticate user;
2. GET `/api/delivery-people` for initial state;
3. connect Socket.IO;
4. emit `dashboard:join` with bearer token;
5. receive `location:update`;
6. update markers without resetting user camera after initial fit.

Existing permission `trackflow:view` remains sufficient for map viewing.

## Notification Center

Notifications are generated by the server and persisted in PostgreSQL.

Initial event types:

- `DEVICE_OFFLINE`;
- `DEVICE_ONLINE`.

Future-compatible event types may include low battery, GNSS failure, geofence and overspeed, but they are outside this MVP.

Each notification contains:

- event type;
- device ID;
- delivery person reference when available;
- title;
- message;
- severity;
- creation timestamp;
- optional resolution timestamp.

Read state is per user through a notification receipt/read table. One user's read action must not clear another user's badge.

## Offline semantics

Reuse the existing status thresholds as the single source of truth:

- online: <= 90 seconds since last location;
- sem sinal: > 90 seconds and <= 5 minutes;
- offline: > 5 minutes.

Do not generate repeated notifications while state remains unchanged.

Transitions:

```text
online/sem sinal -> offline  => DEVICE_OFFLINE
offline -> online            => DEVICE_ONLINE
```

The recovery transition should be detected immediately when new telemetry arrives.

A background server monitor runs every 30-60 seconds to detect devices that became offline while silent.

## Notification API

Protected by `trackflow:view`:

```text
GET  /api/notifications
GET  /api/notifications/unread-count
POST /api/notifications/:id/read
POST /api/notifications/read-all
```

Socket.IO for authenticated dashboard/monitor clients:

```text
notification:new
notification:count
```

## Android bell

The bell is a floating icon on top of the full-screen map.

- unread count appears as a badge;
- tapping opens a notification sheet/panel;
- unread items are visually distinct;
- offline and recovery items include object name/device and relative/absolute time;
- notification list is read-only except marking read/read-all.

This MVP is an in-app notification center. Android OS push notifications/FCM are not required for the first release.

## Security

- monitor requires authenticated user;
- no mobile registration secret is used by the monitor;
- notification endpoints require `trackflow:view`;
- notification read state is scoped to the authenticated user;
- object visibility preferences never leave the Android device.

## MVP acceptance

Server:

- creates one offline event per offline transition;
- creates one online event per recovery;
- persists events;
- supports per-user unread state;
- emits realtime notification events;
- does not spam repeated offline events.

Android Monitor:

- installs as a separate application;
- authenticates;
- shows all objects on a 100% map;
- receives realtime movement;
- user camera is not constantly reset;
- settings can show/hide objects locally;
- bell shows unread badge;
- notification panel can mark events read.
